## 基金实时估值系统（纯后端 → SQLite）

按需求文档实现 `fund_valuation/` 包（23 个模块，约 3.7k 行含测试），**无前端页面**，
唯一产出是 SQLite 中的 `funds` / `holdings_snapshot` / `valuation` 三张表。

- 双轨：`direct`（天天基金 FundValuationLast 的 GSZ/GSZZL）优先，空值降级 `synthetic`
  （前十大权重 × 个股涨跌，**必须除以 coverage 归一化**）；无持仓时用 `fallback_etf` 代理（×95% 仓位假设）
- 数据源实测结论（重要，后续维护必看）：
  - `timeout`=8s、批量估值响应外层是**小写 `data`**（不是 `Datas`）
  - 东财 `api.fund.eastmoney.com/f10/ccmx` 已 404；`ccmx_{code}.html` 已 JS 渲染无表格
  - 移动端 `FundMNInverstPosition` 必须带移动端 UA + `Referer: https://h5.1234567.com.cn/`，否则 ErrCode=61136403
  - 持仓 HTML 解析改走 `fundf10.eastmoney.com/FundArchivesDatas.aspx?type=jjcc`（由 tiantian.py 承担）
  - 腾讯行情 `qt.gtimg.cn/q=` 解析：parts[3]=现价、parts[4]=昨收；涨跌幅自行计算
  - 5xx 开头 6 位代码属沪市（ETF 51xxxx/50xxxx），`normalize_code` 曾误判为 sz
- 置信度分档：coverage >= max_holdings_pct → high；>= 0.75×阈值 → medium；否则 low（含 1e-9 浮点容差）
- 表结构在需求基础上给 `holdings_snapshot` 增加 `report_date` 列（记录季报报告期），旧库自动 ALTER
- 环境：用 uv 建 `.venv`（Python 3.13），`uv pip install -r requirements-dev.txt`；`uv run python -m fund_valuation.main --once`
- 验证：68 项 pytest 全绿；真实网络跑通 4 只基金（api/synthetic/fallback 三种 source 均出现）
- 已删除早期 Streamlit 原型 `app.py` 及 README 中的相关说明（用户确认可删），项目现为纯后端包
