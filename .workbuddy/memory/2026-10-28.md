### 通读代码发现的问题（真实偏差，尚未修）

1. **`holdings_source` 未按基金生效**：`main._primary_holdings_source()` 统计所有基金该字段的
   出现次数取众数，构造一条全局源链；`SyntheticValuator` 全文不引用 `fund.holdings_source`。
   即"每只基金单独指定"实为"全局投票"，少数派基金的配置被忽略。
   修法：让 SyntheticValuator 接收 `{name: source}` 映射，在 evaluate 里按 fund 重排源链。
2. `Quote.change_pct_hint`（腾讯 parts[32]）采集但从未使用，纯预留。
3. `SinaValuationSource` 只回填 gszzl/nav，不填 gsz → 必须靠 direct.py:128 的反推补净值；
   若 nav 也缺，会出现 `status=available` 但 estimated_nav 为 NULL 的边界。
4. `GZTIME` 校验只作用于 direct；synthetic 用实时行情天然当日，但 `base_nav` 的净值日期
   （NavPoint.date）**没有落库**，长假后无法从库判断基准净值是几天前的。

## 修复权重单位缺陷（weight_unit 显式声明）

- 根因：`normalize_weight` 用「>1 才除以 100」推断口径，联接基金残余持仓（0.52 = 0.52%）
  被当成 52%，coverage 冲到 2.53、置信度误标 high。
- 改法：`models.WeightUnit(PERCENT/DECIMAL)` 为枚举；`HoldingsSource.weight_unit` 类属性声明；
  `HoldingsSource._weight_to_decimal()` 统一换算入口；`normalize_weight(value, unit)`、
  `parse_holdings_table(html, weight_unit=...)` 全部改为必传/显式传；删除幅度启发式。
  东财 JZBL 与天天基金"占净值比例"均声明 PERCENT。
- 兜底约定：`test_holdings_source_declares_weight_unit` 断言每个持仓源的**类自身**
  定义了 weight_unit（防新源靠继承默认值蒙混）；回归用例覆盖 "0.52"→0.0052。
- 实测：025506 coverage 2.53→0.0253、007531 1.16→0.0116（均变 low）；
  005827/013083/021964 数值不变（无回归）。11 只基金实跑全成功。
- 连带：PIPELINE.md 权重口径章节重写 + 10 处行号重映射（60→60 全部校验指向 def/关键语句）。

## 新增 GitHub Actions 定时采集（.github/workflows/fetch_data.yml）

- 目标：每 5 分钟 `--once` 跑一轮，数据库跨运行存活。新增 8 步 job，`ubuntu-latest`，
  `timeout-minutes: 5`，`concurrency.cancel-in-progress: false` 串行化（忌两进程同写 SQLite）。
- 持久化方案：`actions/cache` **滚动 key** —— `key: fund-db-${{ github.run_id }}`（永不精确命中，
  逼 post 步骤必存）+ `restore-keys: fund-db-`（前缀取最近一份）。缓存路径含 .db/-wal/-shm 三件套。
  旧缓存由 GitHub 按 10GB LRU 回收；job 被「取消」时 post 不执行 → 该轮增量丢失（不写坏）。
- **关键坑：`env.TZ: Asia/Shanghai`**。代码全是 `datetime.now()` 本地朴素时间，
  runner 默认 UTC 会让 valuation.ts 差 8 小时，并使 `validate_gztime`/`same_day` 在凌晨日期错位。
- 落盘检查步骤：`PRAGMA wal_checkpoint(TRUNCATE)` 后删 -wal/-shm，保证缓存里的 .db 自包含；
  同时把「每只基金最新一条 + 行数 + 库体积」写成 markdown 表格进 `$GITHUB_STEP_SUMMARY`。
- 依赖安装：setup-python 3.13 + `uv venv .venv --python 3.13` + `uv pip install --python .venv/bin/python`，
  跑 `.venv/bin/python -m fund_valuation.main`（不用 uv run，省一次解析）。
- 已实测：摘要脚本在真实库副本上跑通（314 行 / WAL 2MB 合并为 112KB / 11 只基金表格正确）、
  无库降级分支正确；冷启动 `--once` 建库正常（跑完不留 -wal）。
- 计费提醒：288 次/天 ≈ 8640 分钟/月 → 私有仓库免费 2000 分钟约 7 天耗尽，公开仓库不限。
  cron 不保证准时（延迟 5～20 分钟常见），仓库 60 天无提交定时任务自动停用。
- README 加 8.1 节（触发/执行/持久化/串行/可观测 + 6 条注意事项），目录表补 workflow 行，
  测试数 68→75（实际 collected 75）。
